# QarHub — день 3

Автомобильное сообщество Казахстана. React + TypeScript + Vite, сервер Express и общая база SQLite. Участники обсуждают автомобили, добавляют фотографии и знакомятся через профили.

## Запуск

Нужен **Node.js 24 или новее**. На этом компьютере зависимости уже установлены.

```sh
npm install
npm run dev
```

Открой http://127.0.0.1:5173. Команда запускает и интерфейс, и API. В PowerShell можно использовать `npm.cmd` вместо `npm`. Двойной щелчок по `start-qarhub.cmd` также запускает проект и открывает браузер.

Для проверки собранной версии:

```sh
npm run build
npm start
```

Адрес собранного сайта — http://127.0.0.1:3001. `npm run preview` проверяет только статическую сборку; для аккаунтов используй `npm start`.

## Что работает

- Регистрация по email и паролю, вход и выход. Профиль: имя, аватар, город и описание.
- Публичный профиль по ссылке `?member=ID`: публикации и автомобили, которые владелец разрешил показывать. Открывается нажатием на имя автора или из аккаунта.
- До 4 фото в публикации с открытием крупного изображения в новой вкладке. Фото машины: добавление, замена, удаление и настройка видимости.
- Общая лента, вопросы, бортжурналы, ответы и решение, которое выбирает только автор вопроса.
- Гараж, избранное и подписки, доступные после входа в тот же аккаунт с другого браузера.
- Общие счётчики лайков, поиск, фильтры и сортировка.
- Обновление данных при возвращении на вкладку и каждые 8 секунд, пока вкладка видима.
- Сообщения об ошибках сети; текст формы не исчезает при неудачной отправке.
- Мобильный интерфейс и клавиатурная навигация.

Первые 5 публикаций и исходные реакции — демонстрационные и помечены в ленте. Демонстрационные авторы не являются аккаунтами и не имеют паролей. Новые публикации доступны всем посетителям подключённого сервера. Email, избранное и подписки выдаются только владельцу. Гараж по умолчанию скрыт; видимость каждой машины включается отдельно. Существующие машины при обновлении остаются скрытыми.

## Где данные

База создаётся автоматически: `data/qarhub.sqlite`. Дополнительные файлы `-wal` и `-shm` — рабочая часть SQLite. Не удаляй их при работающем сервере.

Перезапуск приложения сохраняет аккаунты, сессии, публикации и гараж. База и резервные копии исключены из Git. Сессия хранится в HttpOnly cookie на 7 дней; браузерный JavaScript не получает её токен. В базе хранится только хеш токена. Пароли хешируются scrypt с отдельной случайной солью.

Данные прототипа первого дня в `localStorage` не удаляются, но новая версия их не использует и не публикует автоматически. Если там есть нужные личные записи, их можно перенести отдельно после проверки.

### Фотографии

Загрузка после входа: JPEG, PNG или WebP до 5 МБ и 25 мегапикселей. Сервер декодирует файл, отклоняет неподдерживаемые и повреждённые изображения, уменьшает до 1920 × 1920 и сохраняет WebP без EXIF, включая GPS. Анимация не поддерживается. Фото хранятся в SQLite и входят в обычную резервную копию.

Черновые фото и снимки скрытых машин доступны только владельцу. Фото публикаций, аватары и снимки открытых машин доступны всем. Если одно фото используется в нескольких местах, достаточно одной публичной ссылки для доступа. Незакреплённые фото старше суток очищаются при следующей загрузке. Ограничение аккаунта: 100 МБ или 500 фото; 30 загрузок в минуту.

### Резервная копия

```sh
npm run db:backup
```

Команда делает согласованную копию через SQLite Backup API, в том числе при работающем сервере. Результат — `backups/qarhub-ДАТА.sqlite`. Для восстановления останови сервер, сохрани текущую базу с её `-wal`/`-shm` отдельно и укажи `DATABASE_PATH` на копию. Не заменяй файлы открытой базы вручную. Резервные копии содержат данные аккаунтов — храни их приватно.

## Доступ с другого устройства в домашней сети

По умолчанию приложение доступно только на этом компьютере. Для домашней сети скопируй `.env.example` в `.env`:

```dotenv
DEV_HOST=0.0.0.0
APP_ORIGINS=http://127.0.0.1:5173,http://localhost:5173,http://192.168.1.10:5173
```

Замени пример IP на адрес своего компьютера в сети, перезапусти `npm run dev` и открой этот адрес на устройстве в той же сети. При необходимости разреши доступ в брандмауэре только для частной сети. `HOST` API можно оставить `127.0.0.1`: браузер обращается к нему через Vite. Для проверки на одном компьютере достаточно обычного и приватного окна браузера.

## Проверки

```sh
npm run build
npm run test:api
npm run test:e2e
# Обе группы:
npm test
```

Серверные тесты проверяют хеширование, cookie, вход/выход, истечение сессий, права авторов, приватность гаража, защиту от запросов с постороннего сайта, валидацию, ограничение попыток входа и сохранность данных при перезапуске.

Браузерные тесты используют Microsoft Edge, отдельные порты 5174/3102 и уникальную базу в `.artifacts/`. Рабочая база `data/qarhub.sqlite` не затрагивается. Тестовые пользователи используют вымышленные email; письма им не отправляются. Скриншоты и временные базы исключены из Git.

## Границы текущего этапа

Это работающая многопользовательская версия для разработки, пока не публичный сервис. Домен и внешний хостинг не подключены. Регистрация не подтверждает владение email; отправка писем, восстановление и смена пароля ещё не реализованы. Также впереди модерация, полноценный каталог моделей, редактирование публикаций и поисковая выдача с постраничной загрузкой. Сейчас API возвращает всю ленту и предназначен для небольшого пробного сообщества.

Перед публичным запуском нужны HTTPS, подтверждение email и восстановление доступа, защита от спама, модерация, резервные копии вне компьютера и мониторинг. В production укажи `NODE_ENV=production` и точный HTTPS-адрес в `APP_ORIGINS`: cookie автоматически получит Secure. Для размещения нужен постоянный диск для SQLite. Запуск API в нескольких процессах потребует общего хранилища ограничителей запросов. При увеличении нагрузки можно перейти на PostgreSQL.

## Тестирование с друзьями через ngrok (Windows)

Ngrok установлен из Microsoft Store. Для подключения аккаунта открой `connect-ngrok.cmd`: войди в личный кабинет, скопируй Authtoken и вставь в локальное окно. Конфигурация хранится вне проекта: `%LOCALAPPDATA%/QarHub/ngrok.yml`. Не добавляй токен в Git или чат.

- Запуск: `start-qarhub-share.cmd` или `npm run share`. Команда собирает сайт, получает HTTPS-адрес ngrok и запускает отдельный сервер на 127.0.0.1:3002.
- Остановка: `stop-qarhub-share.cmd` или `npm run share:stop`. Закрывает только тестовый сервер и его туннель.
- Ссылка появляется в консоли. Компьютер, интернет и процессы должны оставаться включёнными.
- Тестовая база: `data/qarhub-demo.sqlite`. Создаётся с демонстрационными историями; аккаунты и данные из основной базы не копируются. Для тестирования нужна отдельная регистрация. Повторный запуск сохраняет тестовые аккаунты и фото.
- Для резервной копии тестовых данных в PowerShell: `$env:DATABASE_PATH='data/qarhub-demo.sqlite'; npm.cmd run db:backup; Remove-Item Env:DATABASE_PATH`.

Обычный `npm run dev` продолжает использовать основную базу и порты 5173/3001. Публичный запуск использует production-сборку, Secure-cookie и точный разрешённый HTTPS-origin. Прокси доверяется только на loopback, чтобы ограничения запросов различали посетителей. Инспекция содержимого HTTP-запросов в локальном ngrok отключена.

Служебные порты 4047 (ngrok API) и 4046 (остановка с локальным случайным ключом) слушают только 127.0.0.1. Туннель ведёт исключительно на порт 3002. Служебный файл `.artifacts/ngrok-session.json` исключён из Git. Если какой-либо порт занят, запуск завершается без остановки чужого процесса. Для иной установки ngrok укажи переменную `NGROK_BIN` с путём к исполняемому файлу.

Документация: [ngrok для Windows](https://ngrok.com/download/windows), [заголовки прокси ngrok](https://ngrok.com/docs/gateway/endpoints/http#upstream-headers).
